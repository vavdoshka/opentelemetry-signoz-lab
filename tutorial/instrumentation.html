The instrumentation code

All of this app's telemetry comes from about 90 lines of setup and a few calls in the services. None of it is SigNoz-specific. It is standard OpenTelemetry, and you could point it at another backend by changing one variable.

1. Packages

Five OpenTelemetry packages: the SDK, the OTLP exporter, and one instrumentation library for each thing to trace.

2. Configuration lives in env vars

The code never names a service or an endpoint. The SDK reads these standard variables. This is the backend's set:

VariableEffect
OTEL_SERVICE_NAMEBecomes service.name on every span, metric and log. It is the most important setting.
OTEL_RESOURCE_ATTRIBUTESExtra labels on everything, such as deployment.environment=lab.
OTEL_EXPORTER_OTLP_ENDPOINTWhere to send. Port 4318 is OTLP over HTTP.
OTEL_EXPORTER_OTLP_PROTOCOLhttp/protobuf, which avoids a gRPC dependency.
OTEL_PYTHON_FASTAPI_EXCLUDED_URLSSkips spans for Kubernetes health probes.

3. SDK wiring

One function, setup_telemetry(), builds a provider for each signal. The pattern repeats: a provider holds the config, and a processor or reader batches data and hands it to an exporter.

  • Resource.create() reads the two env vars above. Passing the same resource to all three providers is what puts service.name on every signal.
  • BatchSpanProcessor flushes every 5 seconds by default. That is why spans take a few seconds to appear, and the timing also matters for gap 2.
  • Metrics export every 10 seconds here. The SDK default is 60.

6. Custom metrics

Create instruments once, at module level. Then record at the point where the event happens.

Attributes such as order.item become dimensions you can group by. Keep their values to a small set. order.item has four values, which is fine. A per-user value would create a separate time series for each user.

A gauge is different: instead of recording events, you give the SDK a callback, and it reads the current value at each export.

Three instrument types are in use here: a counter for totals (orders.created, scenario.runs), a histogram for distributions (orders.value) and a gauge for a current level (loadgen.target_rps).
