Hands-on tutorial

Learn telemetry by breaking a real app

This tutorial teaches you how to add telemetry to an app with OpenTelemetry, and how to use SigNoz to find out what went wrong. You work on this repo's running lab: a small Python app that fails on demand.

Your browser→ frontend (FastAPI)→ backend (FastAPI)→ Postgres

What you will be able to do

  • Explain traces, metrics and logs, and how they connect.
  • Read real instrumentation code, and add your own spans, metrics and logs.
  • Work through six incidents, from symptom to root cause to fix.
  • Write SigNoz searches for traces, logs and metrics.
  • Spot what a plain install leaves out, including the places where SigNoz can mislead you.

Before you start

  1. Log in to SigNoz in another tab. The login is in .lab-credentials. Links in this tutorial land on the login page if you skip this.
  2. Start some background traffic, so that charts have data. Stop it when you finish.

Your path

Go in order if this is new to you. Each incident stands alone, so you can also jump straight to one. Mark a page complete at the bottom of it. Your progress stays in this browser.

How far to trust what you read

Everything shown as real came from this lab. Each claim says how it was checked, using the same labels as docs/FINDINGS.md:

LabelMeaning
Seen in SigNoz UIRun in the SigNoz web app, and the result was seen on the page.
Query API onlyRun through POST /api/v5/query_range, the endpoint the UI calls, with the same expression. The browser was too slow to confirm it on the page.
ClickHouse SQLRun directly against the database. This is not a SigNoz UI query.
UntestedA proposed fix. It has not been applied or tried in this lab.

About the saved examples

  • Saved trace IDs, numbers and screenshots come from runs on 2026-11-04, mostly during a load run from 23:10 to 00:00 UTC at 5 requests/s with 10% errors. Your live numbers will differ.
  • Screenshots show UTC+1, so 23:10 UTC appears as 00:10. Saved trace IDs exist only in that original lab, so their SigNoz links will not open in yours. Use the live buttons to create your own.
  • SigNoz keeps traces and logs for 15 days, so saved trace links stop working after about 2026-11-19. The pages still show the saved copy.
  • The scenarios fail on purpose, so each root cause is a known line of code. The method is what carries over to real incidents.
