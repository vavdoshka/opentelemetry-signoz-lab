5What keeps it under control

LimitWhy
MAX_BUDGET_USD, $1.00Stops one investigation at Claude Code's own cost estimate. It can overshoot a little. Only Claude Code has this flag
MAX_PER_HOUR, 10A flapping alert can't run up a bill. Past that, it prints that it skipped the alert
MAX_TURNS, 40Stops a loop that isn't getting anywhere
One at a timeIf several alerts fire together, they wait. It keeps cost predictable, at the price of a later answer
One investigation per alertAlertmanager repeats notifications. The alert name and start time identify a firing, so repeats are ignored

It doesn't fix anything. It can't: its SigNoz key and Kubernetes account are read-only. Letting an agent act on production is a much bigger decision than letting it read, and this lab doesn't need it to show the value.

Why it isn't a service in the cluster

We first built this as a pod running Claude Code. It worked, and it had the same results. But it needed things that added nothing here:

A pod neededYour own agent has
Its own login: a year-long token in a SecretThe login you already have
A 438 MB image, with Claude Code and kubectl pinned insideBoth already installed
A web server, a queue and a page to look afterA short script, and your terminal
A second alert channel on the rulesLab 4's sink, as it is

The cost of the simpler way: it only runs while your machine is on and the script is running. On a team, you'd want investigations to run when nobody's laptop is open, so you would run the same command somewhere that stays up, with its own login and limits. That's a deployment decision, not a different design: the workspace, MCP server and read-only accounts stay the same.
