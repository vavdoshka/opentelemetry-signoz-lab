How SigNoz is configured

Nothing here is hidden. This page lists every piece of SigNoz configuration in the lab, where it lives, and why it exists. If something isn't listed, it's at its default.

The pieces

PieceWhat it doesConfigured in
SigNozUI, API, ClickHouse, ZooKeeper and the collectors, from the official Helm chartsignoz/signoz-values.yaml
k8s-infraNode agents and a cluster collector: pod and node metrics, container logs, Kubernetes eventssignoz/k8s-infra-values.yaml
OpenTelemetry OperatorInjects the agent into your pods. Not part of SigNozcluster/otel-operator-values.yaml
InstrumentationTells the Operator how to instrument each lablabs/*/k8s/instrumentation.yaml
IngressServes the UI at signoz.localhost:8080signoz/ingress.yaml
First adminCreated automatically. The collector opens no OTLP ports until an organization existsscripts/bootstrap_signoz.py
DashboardThe lab's one dashboardlabs/lab2-custom-dimensions/dashboard.json

What was changed from the defaults

SettingWhy
otelCollector.replicaCount: 2Keeps ingestion running if a node dies. It's the only change to the SigNoz chart
otelCollectorEndpoint in k8s-infraRequired, with no default. It must include http://, or exports fail while pods stay Running
global.clusterName in k8s-infraLabels data with a cluster name. It's blank by default
autoGenerateCert.recreate: false on the OperatorStops helm upgrade briefly breaking injection, which fails silently

Everything else is a chart default, including retention: 15 days for traces and logs, 30 days for metrics.

Dashboards

A new SigNoz install has no dashboards, and this lab adds exactly one: Lab 2: custom dimensions. make lab2 creates it through the API with scripts/create_dashboard.py, and leaves it alone if it already exists. To change it, edit it in the SigNoz UI, or change the JSON file and delete the dashboard before rerunning.

A panel's groupBy must declare the right type. cache.hit is a boolean, and declaring it as a string makes the panel silently empty.

SigNoz publishes ready-made dashboards at SigNoz/dashboards, including k8s-infra-metrics and apm. To add one, use Dashboards, then New dashboard, then Import JSON in SigNoz. The lab doesn't import any, so how well they fit this data is untested.

Alerts, channels and log pipelines

There are none, by choice. SigNoz starts with none, and this lab adds none.

How much it uses

Measured on this lab, with both labs running on k3d:

IdleLoad generator at 5 requests/s
All pods, CPUAbout 0.5 coreAbout 0.8 core
All pods, memoryAbout 5.3 GiBAbout 5.4 GiB
ClickHouse0.3 core, 3.1 GiB0.5 core, 3.2 GiB
ZooKeeper0.05 core, 0.9 GiB0.08 core, 0.9 GiB
Docker Desktop's VM on the MacAbout 0.6 coreAbout 2.2 cores

The Docker VM costs more than the pods do, because virtualization adds overhead. Memory barely changes with traffic. It's mostly the fixed cost of running ClickHouse and ZooKeeper.

ClickHouse also logs heavily about itself. In one measurement it held 1.83 GiB of its own system logs, against about 150 MiB of actual telemetry.

To free your machine, stop the load generator when you aren't using it, and run k3d cluster stop signoz-lab between sessions. make up brings everything back.
