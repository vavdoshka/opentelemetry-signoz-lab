How SigNoz is configured

Nothing here is hidden. This page lists every piece of SigNoz configuration in the lab, where it lives, and why it exists. If something isn't listed, it's at its default.

What was changed from the defaults

SettingWhy
otelCollector.replicaCount: 2Keeps ingestion running if a node dies
otelCollector.config.processors.batch.timeout: 5sDefault 1s. Fewer, larger writes cost ClickHouse much less CPU. Data appears up to 5 seconds later
clickhouse.filesTurns off five of ClickHouse's logs about itself, which wrote more rows than the telemetry it stores
clickhouse.zookeeper.heapSize: 256The default 1 GB heap is far more than this lab needs
otelCollectorEndpoint in k8s-infraRequired, with no default. It must include http://, or exports fail while pods stay Running
global.clusterName in k8s-infraLabels data with a cluster name. It's blank by default
autoGenerateCert.recreate: false on the OperatorStops helm upgrade briefly breaking injection, which fails silently

Everything else is a chart default, including retention: 15 days for traces and logs, 30 days for metrics.

Why ZooKeeper, and not ClickHouse Keeper?

ClickHouse has its own coordination service, ClickHouse Keeper, which it describes as replacing ZooKeeper. ZooKeeper still works, and this lab runs what SigNoz supports: chart 0.149.0 installs ClickHouse 25.12.5 with ZooKeeper 3.7.1, and has no Keeper option.

Use of Zookeeper asks whether SigNoz will follow ClickHouse. It had no reply on 2026-11-07.

Dashboards and views

Lab 1 uses only what's built into SigNoz. Services, Traces, Logs, Exceptions, Service Map, Metrics Explorer and Infra Monitoring all work with no setup, so make up creates no dashboards or saved views.

The Dashboards page itself starts empty. This lab adds exactly one dashboard, in Lab 2: Lab 2: custom dimensions. make lab2 creates it through the API with scripts/create_dashboard.py, and leaves it alone if it already exists. To change it, edit it in the SigNoz UI, or change the JSON file and delete the dashboard before rerunning.

A panel's groupBy must declare the right type. cache.hit is a boolean, and declaring it as a string makes the panel silently empty.

SigNoz publishes ready-made dashboards at SigNoz/dashboards, including k8s-infra-metrics and apm. To add one, use Dashboards, then New dashboard, then Import JSON in SigNoz. The lab doesn't import any, so how well they fit this data is untested.

Alerts, channels and log pipelines

There are none in Labs 1 and 2. SigNoz starts with none, and those labs add none.

How much it uses

Measured on this lab, with both labs running on k3d:

IdleLoad generator at 5 requests/s
All pods, CPU0.25 to 0.3 core0.6 to 0.7 core
All pods, memoryAbout 4.3 GiBAbout 4.4 GiB
ClickHouse0.12 to 0.17 core, 2.6 GiB0.23 to 0.35 core, 2.7 GiB
ZooKeeper0.02 core, 0.4 GiB0.03 core, 0.4 GiB
Docker Desktop's VM on the Mac0.5 to 0.9 core0.6 to 1.6 cores

The Docker VM costs more than the pods do, because virtualization adds overhead. Memory barely changes with traffic. It's mostly the fixed cost of running ClickHouse.

What reduced ClickHouse's load

BeforeAfter
ClickHouse's logs about itselfAbout 165,000 rows a minuteAbout 4,500 rows a minute
Writes in the test window5,7751,672
ClickHouse CPU under load0.4 to 0.7 core0.2 to 0.3 core
All pods, memoryAbout 5.4 GiBAbout 4.4 GiB

The self-logging cost disk and memory, not CPU. In one measurement it took 1.83 GiB, against about 150 MiB of telemetry. The CPU went on writes: with a 1-second batch, ClickHouse took about 24 small writes a second. Other containers on the machine were quieter in the second run, so the CPU figure is partly confounded, but the write counts aren't.

To free your machine, stop the load generator when you aren't using it, and run k3d cluster stop signoz-lab between sessions. make up brings everything back.
