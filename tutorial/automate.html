Automate it

Everything in Labs 3 and 4 is scripted, so you can use the same pieces on your own cluster. This page shows how, with a proper identity instead of a password, and the traps that turned up when we tested it.

2. Give automation its own identity

Don't put a person's password in a pipeline. make lab3 uses the lab's login only because it created that login itself. For anything else, create a service account: Settings, then Service Accounts, then New Service Account. Give it a role and a key, and keep the key in your secret store.

Roles matter, so we tested each one with a real key:

RoleRead dashboards and rulesCreate dashboards and rulesCreate channels

So use signoz-editor day to day. Channels change rarely, so create them once with an admin, in the UI or with a separate key. An editor key can still list them, and rules can name them.

Three traps

All three turned up when we tested this, and each would pass unnoticed in a pipeline:

TrapWhat happensWhat to do
Repeat runsPosting the same dashboard twice creates two copies, with no errorCheck by name first, as create_dashboard.py does
A wrong path looks like successSigNoz answers unknown paths with its web page and a 200, so curl -f passesCheck the reply is JSON. Don't trust the status alone
A role assigned the wrong wayFor the same reason, a mistyped role request returned 200 and did nothing. Every call then got a 403Use POST /api/v1/service_account_roles, and test the key afterwards

SigNoz publishes its API, with worked examples, as docs/api/openapi.yml in its repo. Use the file from the tag you run.

Terraform

SigNoz also publishes a Terraform provider, version 0.1.6 at the time of writing, with resources for dashboards, rules, channels and service accounts. It's worth a look if you already use Terraform. Untested We read its documentation but haven't run it, so this is what the documentation says:

  • It takes the same kind of service account key, through SIGNOZ_ACCESS_TOKEN, and the URL through SIGNOZ_ENDPOINT.
  • Its dashboards are typed HCL in snake_case, such as refresh_interval, while exported dashboards are camelCase JSON. So you probably can't load an exported JSON file as it is.
  • It supports terraform import, so you could build a dashboard in the UI and bring it under Terraform.
