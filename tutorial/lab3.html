Lab 3: Kubernetes

What Kubernetes tells you

Labs 1 and 2 watch your app. This lab watches what it runs on: pods, nodes, the kubelet and the API server. Some of that comes free, but the signals that explain the worst failures don't. You'll see what they cost, and which metrics quietly mislead you.

Start it

Run make lab3. It takes a minute or two, and it does four things:

  1. Deploys a small workload in namespace lab3. Like Lab 1, it has no OpenTelemetry code.
  2. Adds four scrape jobs to the cluster collector that k8s-infra already runs.
  3. Gives that collector permission to read them.
  4. Creates five dashboards: four from SigNoz, and one for this lab.

Start some load, at the lab's page or here. Use 2 requests/s unless a page says otherwise. Stop it when you finish.

A workload with real limits

Labs 1 and 2 set no limits and no liveness probes, so nothing here could be throttled, OOM killed or restarted by a probe. This workload sets them, because those are what make Kubernetes step in:

Three things to notice:

On k3s, it's all one process

k3s runs the API server, scheduler, controller manager and kubelet in one process, sharing one set of metrics. You can see that in what each endpoint returns:

EndpointSeriesMetric names
API server /metrics32,461454
Kubelet /metrics on the server node32,429454
Kubelet /metrics on the worker node1,797227

The first two are nearly the same data. That makes the keep-list more important here, because a plain scrape of both would store everything twice. It also means the API server's endpoint gives you the scheduler's metrics on k3s, which you wouldn't get on a real cluster.

You can see this on the dashboards. Go Routines reads about 11,600, double the real 5,600 or so, because the kubelet and apiserver jobs both report the same process.

A real API server

The apiserver job finds the API server through the kubernetes Service in default, so the same job works on other clusters, and CI runs it on kind. What changes is everything around it:

Componentk3s, as in k3dkubeadm clusters, such as kind
API server/metrics on port 6443The same
SchedulerIn the API server's metricsIts own endpoint on port 10259, bound to localhost by default
Controller managerIn the API server's metricsIts own endpoint on port 10257, bound to localhost by default
DatastoreSQLite, so there's no etcd to scrapeetcd, with metrics on port 2381, bound to localhost by default
KubeletPort 10250 on each nodeThe same

CI proves the apiserver and kubelet jobs on kind. The ports for the other components are kubeadm's usual defaults, and weren't checked in this lab. What it costs

You asked SigNoz to store more, so it costs something. Measured idle, with all the labs running:

Before Lab 3With Lab 3
Samples a minute, all of SigNoz32,63651,493
ClickHouse CPU0.12 to 0.17 core0.12 to 0.17 core
ClickHouse memory2.6 GiB3.1 GiB
Cluster collector memory67 MiBAbout 220 MiB
All pods, memory4.3 GiB5.2 GiB

The scrape jobs add about 6,000 series. The sample count also includes Lab 3's own two instrumented pods, and the memory figures include those pods and Lab 4's sink. We can't say how much of ClickHouse's rise is new data and how much is caching from opening dashboards.

Each job started with a shorter keep-list, which left some community dashboard panels empty. Filling them all added 17% more samples, and made no measurable difference to ClickHouse's CPU or memory at this size. So the lab keeps them. On a big cluster these series multiply, so measure before you copy this.

  • Collector memory rises whatever you keep, because it has to read about 73,000 lines every 30 seconds before throwing most of them away.
  • The API latency histogram is the biggest single item. It's about 4,250 series, for one panel. It stays because P99 latency is the main measure of API server health. If you don't need it, remove apiserver_request_sli_duration_seconds_(bucket|sum|count) from the keep-list.
  • A switch you might not expect. Turning on presets.prometheus also starts a job that scrapes SigNoz's own ClickHouse, ZooKeeper and collectors. That added 5,239 series, so this lab limits it to namespace lab3, which turns it off.
