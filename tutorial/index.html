Hands-on tutorial

Learn telemetry by breaking a real app

This tutorial teaches you what OpenTelemetry can do for an app with no code at all, how to add detail only where you need it, how to watch the Kubernetes underneath, and how to get alerted. You work on small Python apps that fail on demand.

What you will be able to do

  • Explain traces, metrics and logs, and how they connect.
  • Get traces, logs and metrics from an app without touching its code.
  • Work through six incidents using that telemetry alone, from symptom to root cause to fix.
  • Add a dimension where you need one: first a field on a log line, then an attribute on a span, then a metric.
  • Work through four incidents that show what those dimensions buy you.
  • Debug throttling, OOM kills, failed probes, and node and API server problems.
  • Write alerts on metrics, traces and logs, and prove that they reach you.
  • Write SigNoz searches for traces, logs and metrics.
  • Spot what a plain install leaves out, including the places where SigNoz can mislead you.

Before you start

  1. Run make up. That is all you need for Lab 1. Run make lab2, make lab3 and make lab4 when you reach each one.
  2. Log in to SigNoz in another tab. The login is in .lab-credentials. Links in this tutorial land on the login page if you skip this.
  3. Start some background traffic, so that charts have data. Stop it when you finish.

Your path

Go in order if this is new to you. Each incident stands alone, so you can also jump straight to one. Mark a page complete at the bottom of it. Your progress stays in this browser.

About the saved examples

  • Saved trace IDs, numbers and screenshots come from real runs on 2026-11-07, on the labs as they are now. Each page's saved examples come from the lab it teaches. Load figures come from a run from 11:10 to 11:21 UTC at 5 requests/s with 10% errors, on both labs. Your live numbers will differ.
  • Screenshots show UTC+1, so 11:00 UTC appears as 12:00. Saved trace IDs exist only in the lab that made them, so their SigNoz links will not open in yours. Use the live buttons to create your own.
  • SigNoz keeps traces and logs for 15 days, so saved trace links stop working after about 2026-11-22. The pages still show the saved copy.
  • The scenarios fail on purpose, so each root cause is a known line of code. The method is what carries over to real incidents.
